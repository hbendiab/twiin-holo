Architecture Twiin

Ce que Twiin utilise aujourd'hui à chaque étape, et pourquoi. Twiin observe une tâche faite une fois par un salarié, la comprend, la fait valider, la reproduit dans un environnement de test isolé, essaie plusieurs solutions, puis propose la meilleure : accélérer (conseils, tuto) ou automatiser (n8n, avec Holo seulement là où il n'y a pas d'API).

Règles qui traversent toutes les étapes

  • Sécurité des données : aucune touche tapée n'est enregistrée ; les essais se font uniquement dans le jumeau ; tout clic sur « valider », « payer », « envoyer » ou « supprimer » est bloqué.
  • Isolation par entreprise : chaque salarié se connecte avec son compte ; Supabase ne lui montre que les données de son entreprise (RLS testée).
  • Tout est mesuré : chaque essai écrit sa durée, son nombre d'appels, sa réussite vérifiée et les faux « réussis » dans tests.
  • Mac et Windows : le même code détecte le système ; scripts/doctor.py vérifie un poste sans afficher aucun secret.
  • À trancher en équipe : un seul projet Supabase, mais deux jeux de tables dans le code. Celles d'Alexis (dictionnaire, taches, tests, recommendations) sont en service ; celles de Hanine (profiles, audits, tasks, tutos, automations, automation_runs, back_log) sont préparées, pas appliquées. recommendations existe déjà avec d'autres colonnes, et tasks double taches.
  • Secrets : jamais dans le dépôt. Aujourd'hui dans un fichier .env local (environnement de l'équipe) ; demain uniquement côté serveur.

Version finale visée

En version finale, le salarié n'installe et ne configure rien : il se connecte avec le compte de son entreprise et utilise Twiin. Tout le calcul tourne dans le cloud, dans des environnements jetables.

  • Sur le poste, seulement un petit capteur (captures, OCR, journal d'actions), déployé par la DSI, avec son propre Python et navigateur. Il ne contient aucune clé.
  • Une application web Twiin hébergée (UE) : parcours employé, page Back pour l'équipe.
  • Des workers dans le cloud, un conteneur jetable par tâche : jumeau, 3 itérations « conseil », 2 itérations « automatisation », réseau fermé sauf les API utiles.
  • Un n8n par entreprise, hébergé (n8n Cloud ou auto-hébergé en Docker, région UE), où Twiin livre le workflow retenu.
  • Les clés uniquement côté serveur (coffre de secrets) ; connexion des salariés par SSO (Microsoft, Google) via Supabase Auth.
  • Holo hébergé pour les logiciels web sans API ; agent local seulement pour les logiciels de bureau sans API.
  • Limite connue : sur Mac, l'autorisation d'enregistrer l'écran doit être donnée une fois par l'utilisateur (règle d'Apple).
